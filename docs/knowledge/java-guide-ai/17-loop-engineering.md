# 17｜Loop Engineering

来源：[JavaGuide 原文](https://javaguide.cn/ai/agent/loop-engineering.html)

## 外层循环

Agent Loop 是一次任务内部的“推理 → 行动 → 观察”；Loop Engineering 是把多次任务执行接起来的外层流程：CI、PR、定时器或人工事件触发下一轮，系统准备证据和权限，Agent 执行，测试/评估判断结果，状态保存继续/停止/交人工。

外层循环真正关注三件事：下一轮需要哪些证据，哪些动作必须暂停，前一轮状态保存在哪里。Prompt、Context、Tool 和 Harness 决定单轮如何跑；Loop 负责调度、验证、恢复和下一轮入口。

## 触发和停止

按时间、事件、目标或人工审批触发的 Loop 都可以成立。文章用 `/loop` 和 `/goal` 做对照：前者主要表示按时间再次观察，后者表示按可验证完成条件持续推进；这些是外部产品能力示例，不是本项目指令，也不应直接复制到 ServiceFlow。

可执行目标要写范围、命令、成功信号、最大轮数、无进展条件和人工接管条件。“优化一下”不能作为停止判断。测试退出码、CI 状态、lint、截图、diff 或业务后置状态可以提供证据；Agent 自评只能补充。

## 建议的第一版

文章建议从只读 CI triage 开始：读取规则、失败日志、相关文件和最近提交，区分环境抖动、测试不稳定、代码回归和依赖问题；能复现就跑最小测试，不能复现就保留证据；结果写入外部状态，并标记自动修复/需负责人/疑似偶发。不要自动改代码、开 PR、发消息或改生产配置。

状态至少记录目标、范围、item、证据、已执行动作、结果、下一步、轮数、预算和停止原因。稳定后再逐步开放独立 worktree、修改白名单、指定命令、目标测试、草稿 PR和人工 review。权限级别应从只读摘要、本地复现、草稿修复、创建 PR 到自动合并逐级放行。

## 风险与对 009 的落点

Loop 容易遇到虚目标、弱验收、自评代替验收、成本无上限和权限过大。生产数据库写入、权限变更、发布和支付不适合默认无人值守。对 009，2.0 只有在形成稳定可观察的回归/诊断任务后才考虑外层自动循环；当前这份知识库的创建不是授权自动改代码或轮询外部系统。
