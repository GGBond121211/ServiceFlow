# 项目背景与作品集定位

## 1. 个人背景

项目所有者是大三计算机专业学生，目标是申请国内大厂 Agent 开发日常实习。已有项目 CodeInsight 主要证明代码检索、RAG、Coding Agent、多 Agent Bug 修复、Docker 沙箱和 SWE-bench 子集评测能力。

ServiceFlow 作为第二项目，需要避免再次做代码理解或通用知识库，而是证明 Agent 能够进入一个普通业务系统，围绕数据库状态和工具调用完成可验证任务。

## 2. 项目要回答的简历问题

完成后，项目应当用代码和评测回答以下问题：

1. 能否把自然语言请求映射为结构化业务意图？
2. 能否让 Agent 查询数据库并调用业务工具，而不是只生成文字？
3. 能否用 LangGraph 表达补充信息、规则判断、审批和执行分支？
4. 能否使用 MySQL 保存订单、工单、退款和会话状态？
5. 能否用 FastAPI 暴露清晰的 HTTP JSON 接口？
6. 能否使用 Docker Compose 让他人一条命令启动演示环境？
7. 能否用固定案例和最终数据库状态量化 Agent 效果？
8. 能否说明 LLM 应该负责什么、确定性代码应该负责什么？

## 3. 项目与真实生产系统的关系

项目不声称复刻任何公司的售后后台，也不使用真实企业数据。所有规则、订单和对话都是为学习和评测设计的模拟数据。

真实性来自以下工程事实，而不是数据来源：

- 业务状态真实写入数据库；
- 每个工具有明确输入、输出和副作用；
- LangGraph 有真实条件分支；
- 测试和评测可以重复执行；
- 最终结果由数据库状态而不是模型自我宣称判断；
- README 中所有指标均由仓库脚本生成。

## 4. 预期面试演示

演示控制在五分钟内：

1. 用 Docker Compose 启动 API 和 MySQL；
2. 打开浏览器售后页面；
3. 输入一个可直接处理的取消订单请求；
4. 输入一个需要人工审批的高金额退款请求；
5. 展示 Agent 工具轨迹和数据库最终状态；
6. 打开固定评测报告，解释成功案例、失败案例和下一步改进。

## 5. 学习目标

- 掌握 MySQL 在普通 Python 后端中的基本使用；
- 理解 SQLAlchemy 模型、Session、事务和仓储实现；
- 掌握 Dockerfile 与 Docker Compose 的基本职责；
- 巩固 FastAPI、Pydantic、pytest 和 Ruff；
- 掌握 LangGraph 单 Agent 状态图、条件边和人工恢复；
- 学会设计以业务最终状态为主的 Agent 评测。

## 6. 工期与完成标准

建议按 Task 顺序在 6 至 8 周内完成。项目不以代码量或测试覆盖率为目标；第一阶段最终使用核心40案与复杂中文60案共100案评测，并以核心流程、浏览器演示、Docker Compose 和作品集文档的真实证据作为验收依据。
